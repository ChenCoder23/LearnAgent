## 01 语法核心：容器、字符串、可变性

| 容器 | 底层 | 查找 | 适合 |
| --- | --- | --- | --- |
| `list` | 动态数组 | O(n) | 有序、按下标访问、频繁追加 |
| `dict` | 哈希表 | O(1) | 按 key 取、去重、分组、计数 |
| `set` | 哈希表 | O(1) | 成员判断、去重、集合运算 |
| `tuple` | 定长数组 | O(n) | 不可变记录、可哈希、当 dict 的 key |

**可变性**是本章真正的主题。`list/dict/set` 可变，`int/str/tuple/frozenset` 不可变。
判断一个 bug 是不是「可变对象共享」引起的，只问一句：**这个对象是不是被两个地方同时持有？**

```python
def add_tag(tag, tags=[]):      # 错：默认值只在函数定义时创建一次
    tags.append(tag)
    return tags

def add_tag(tag, tags=None):    # 对
    tags = list(tags) if tags is not None else []
    tags.append(tag)
    return tags
```

## 02 函数、作用域、闭包、装饰器

LEGB：Local → Enclosing → Global → Builtins。闭包就是「内层函数记住了外层函数的变量」：

```python
def make_counter():
    count = 0
    def counter():
        nonlocal count      # 没有 nonlocal 就只能读，不能改
        count += 1
        return count
    return counter
```

两个经典坑：

- **延迟绑定**：`[lambda: i for i in range(3)]` 全是 `2`，闭包捕获的是变量而不是当时的值；
- **默认参数求值时机**：默认值在 `def` 执行时求值，所以可变默认值会被所有调用共享。

装饰器本质是「接收函数、返回函数」：

```python
def retry(func=None, *, times=3):
    def decorator(target):
        @wraps(target)
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return target(*args, **kwargs)
                except Exception:
                    if attempt == times:
                        raise       # 直接 re-raise，保留原始 traceback
        return wrapper
    return decorator(func) if func is not None else decorator
```

`@tool`、`@app.get`、`@pytest.fixture` 全是这个模式。这一章学不好，后面所有框架都会变成「魔法」。

## 03 面向对象与魔术方法

写值对象（Value Object）要守三条纪律：

1. 不可变（`frozen=True` 或只读属性）；
2. `__eq__` 与 `__hash__` 语义一致（相等就同哈希）；
3. `__repr__` 能直接看出内容，方便调试。

`super()` 是**协作式**的，不是「调用父类」这么简单：多继承下它按 MRO 找下一个类。
每个 `__init__` 都要 `super().__init__(*args, **kwargs)` 转发参数，否则链条会断、参数会丢。

描述符（`__get__`/`__set__`）是属性系统的底层机制，`property`、ORM 字段、校验器都基于它。
理解它，你就能解释「为什么 `product.price = -1` 会报错」。

## 04 迭代器、生成器、上下文管理器、异常

**迭代器协议**只有两个方法：`__iter__` 返回自己，`__next__` 返回值或抛 `StopIteration`。
迭代器是**一次性**的，这是它与 list 最本质的区别。

生成器函数（含 `yield`）免费带给你惰性求值：内存 O(1)，还能表示无限序列。

```python
def read_in_batches(lines, size):
    batch = []
    for line in lines:
        batch.append(line)
        if len(batch) == size:
            yield batch
            batch = []
    if batch:
        yield batch
```

`@contextmanager` 把「进入/退出」写成一个函数，`try/finally` 语义自动成立：

```python
@contextmanager
def transaction(store):
    snapshot = dict(store)
    try:
        yield store
    except Exception:
        store.clear(); store.update(snapshot)
        raise
```

异常要有层次（`AppError` → `NotFoundError`/`ValidationError`），并用 `raise ... from` 保留根因，
否则线上只剩一句 «KeyError»，你根本不知道是谁抛的。

## 05 类型注解、Protocol、Pydantic、日志

- 注解首先是**给人看的文档**，其次才给 mypy；
- `Protocol` 表达「我不关心你的类是谁，只关心你长什么样」，这是依赖注入与可测试性的基础；
- Pydantic 用来守**系统边界**（HTTP 请求体、LLM 结构化输出），不要拿它当领域逻辑；
- 日志用 JSON + `contextvars` 注入 `request_id`，才能在并发下把一次请求的日志串起来；
- 写文件用「临时文件 + `os.replace`」保证原子性，直接覆盖可能写出半个文件。

## 06 并发与异步

| 任务类型 | 首选 | 原因 |
| --- | --- | --- |
| 网络/数据库/磁盘（IO 密集） | 线程池 或 asyncio | 等待期间可以切换任务 |
| 纯计算（CPU 密集） | 多进程 / C 扩展 | GIL 只允许一个线程执行字节码 |
| 大量长连接 | asyncio | 单线程事件循环，内存开销小 |

```python
sem = asyncio.Semaphore(5)          # 限流：保护下游
async with sem:
    await fetch()
```

手动实验：`uv run python labs/06_concurrency_async/demo_gil.py`。你会看到 CPU 密集任务用线程几乎不加速，
用进程接近线性加速。**结论自己跑出来，比背下来牢得多。**

## 07 Python 原理

- **小整数缓存**：-5..256 是同一对象；`int("1000")` 每次新建；
- **字符串驻留**：相同字面量同一对象，运行时拼接不是；
- **引用计数**：`sys.getrefcount` 能看到引用数，减到 0 立即回收；
- **循环引用**：引用计数处理不了，靠 gc 分代回收；
- **字节码**：`dis.get_instructions` 能看出推导式与循环的真实执行方式；
- **属性查找**：实例 `__dict__` → 类 `__dict__`（描述符优先）→ `__getattr__` 兜底；
- **深浅拷贝**：浅拷贝共享内层对象，深拷贝递归复制且慢很多。
