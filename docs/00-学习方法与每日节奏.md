# 学习方法与每日节奏

## 为什么这个项目要写成「练习驱动」

编程能力分成三层：**认得**（看代码能懂）、**写得出来**（空白文件能默写）、**判断得对**（知道哪种写法在该场景更合适）。
只有第二、三层值钱，而它们只能靠手打 + 反馈获得。

所以这里每一章都是同一个结构：讲义讲原理 → `lab.py` 留空 → `tests/` 当验收 → `solutions.py` 做对照。
测试不是「老师批改」，而是**你随时能自己跑的需求文档**。

## 每天 60 分钟的标准流程

| 时间 | 做什么 | 目的 |
| --- | --- | --- |
| 0–10 min | 读讲义对应小节，写下「这章要解决什么问题」 | 先有目标，避免盲目抄 |
| 10–40 min | 逐题实现 `lab.py`，每题写完立刻跑单章测试 | 小步快跑，缩短反馈环 |
| 40–50 min | 卡住的题看 `solutions.py`，关掉后**重写一遍** | 把「看懂」转成「写出」 |
| 50–60 min | 口头复述今天的 3 个要点，记一句到错题本 | 主动回忆比再读一遍有效 |

## 卡住时的三级求助（按顺序，不要跳）

1. **看测试**：失败信息会告诉你输入、期望、实际，多半能自己找到方向。
2. **看该函数的 docstring**：里面写了规则、边界和可以用的标准库线索。
3. **看 `solutions.py`**：只看卡住的那一个函数，然后**合上重写**——这是关键动作。

如果一整章都看不懂，说明前置章节没吃透，回上一章把对应测试重跑一遍。

## 打卡与复盘

```powershell
uv run python -m learnkit.progress            # 看整体进度
uv run python -m learnkit.progress --stage 1  # 只看阶段一
```

复盘只记三行：**今天学会了什么 / 卡在哪 / 明天第一件事**。不要写长篇笔记，那是拖延的伪装。

## 自测掌握程度的三个问题

每章结束前，脱离代码回答：

1. 这个知识点解决什么问题？不用它会发生什么？
2. 代码里哪一行是关键？删掉它会怎样？
3. 换个需求（并发更高 / 数据量更大 / 要持久化），这套写法哪里会先崩？

答不出第 3 题很正常，但你要能说出**先量一下、再优化**，而不是凭感觉改代码。
