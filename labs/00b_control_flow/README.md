### 表达式产出值，语句安排动作

`2 + 3`、`age >= 18`、`name.upper()` 都是表达式，它们会计算出一个值。赋值、if、for、return 则在安排程序怎么往下走。你写代码时可以先想清楚：现在是在算一个值，还是在决定下一步做什么？

比较表达式本身就返回 bool，所以条件判断的结果可以直接返回。Python 也提供条件表达式 `a if condition else b`，适合表达简单的二选一；分支里需要做很多事时，还是展开成 if 更清楚。

运算顺序按优先级决定，括号能明确你的意图。`/` 是除法，`//` 是向下取整的整除，负数时不能理解成简单截掉小数；`%` 是余数，`**` 是幂。

```python
assert 7 / 2 == 3.5
assert -7 // 2 == -4
assert 1 < 2 < 3  # 连续比较会串联比较关系
answer = "yes" if 3 > 2 else "no"
assert answer == "yes"
```

Python 会把 `a < b < c` 理解成两段比较，中间的 b 只求值一次。想判断某个比较结果是不是 True，写 `(3 >= 2) is True` 更直接；实际代码通常直接用 `3 >= 2` 就行，不需要和 True 再比较一次。

### 控制流靠缩进表达层次，边界决定分支有没有漏

Python 用缩进表示代码属于哪一块，所以缩进是语法的一部分。if/elif/else 从上往下找第一个成立的条件；for 从可迭代对象逐项取值；while 在每次进入循环体之前重新检查条件。

for 适合“我要把这一组东西走一遍”，while 适合“我要一直做到某个状态为止”。while 里尤其要想清楚哪一行会改变状态，不然条件可能一直成立。range 采用左闭右开的范围，切片也是同一套约定，这让相邻区间比较好衔接。

```python
visited = []
for number in range(1, 5):
    if number == 2:
        continue
    if number == 4:
        break
    visited.append(number)
assert visited == [1, 3]
```

continue 结束当前这一轮，break 结束当前循环，return 结束整个函数，作用范围不同。边界最好拿具体值走一遍，比如“刚好等于阈值”究竟走哪边。你也可以在每轮之后说一句当前状态的含义，这种检查方式叫循环不变量，比盯着循环猜更靠谱。

### 迭代协议把数据来源和处理方式分开

for 不需要知道数据来自列表、文件还是无限数字流，它只需要拿到迭代器，再反复请求下一项。可迭代对象提供 __iter__，迭代器提供 __next__，结束时抛 StopIteration。这套小协议让不同数据源能接上同样的处理代码。

```python
source = iter([10, 20])
assert next(source) == 10
assert list(source) == [20]
assert list(source) == []
```

列表本身可以多次创建新迭代器，具体迭代器通常是一次性的。把“可迭代”和“当前这趟遍历的游标”区分开，你就不会奇怪为什么读完后第二次没东西。

函数里有 yield，Python 会替你管理暂停位置，得到生成器。它让逐项处理不用手写完整的游标状态，但计算也延后了，里面的异常可能到 next 时才出现。send 可以把值送回 yield 表达式，第一步通常要先 next 预热；这和 async/await 协程有联系，但普通生成器并不是 asyncio 任务。

## 原理明白了，再看看这章会怎样用到它们

### 分支判断

if/elif/else 按书写顺序选择第一个成立的分支。grade 先验证 0..100，再从高分往低分判断；FizzBuzz 先处理同时整除 3 和 5 的情况。

### 计数循环

for 遍历可迭代对象。range(1, n + 1) 包含 1 和 n，结束值不包含；n < 1 时它为空，因此累加器保留初始的 0。

### 条件循环

while 每轮先检查条件。倒计时每轮减 1；sum_until_over 在 total <= limit 时继续，因此刚好等于 limit 仍要再加一次。

### 搜索与提前结束

enumerate 同时给出下标和值。find_first_even 返回下标，找不到返回 -1；return 可以直接退出函数，break 只退出当前循环。

### 质数与平方根边界

小于 2 不是质数。若 n 有因子，至少一个因子不大于平方根，所以只需检查 divisor * divisor <= n；等号不能漏，否则完全平方数可能被误判。

## 顺着这章，还能多理解一点什么

算法正确性可以用循环不变量解释：sum_to 每轮之后 total 是已经访问的整数之和。搜索、过滤、累加分别对应提前退出、选择保留和更新状态。

## 先看一小段代码，把语法拆开聊

```python
total = 0
for value in range(1, 4):
    if value % 2 == 0:
        continue
    total += value
assert total == 4
```

+= 是累加赋值，% 2 == 0 判断偶数，continue 跳过本轮剩余语句。range(1, 4) 产生 1、2、3。

顺便认一下题目里常见的注解：`list[str]` 是“里面放字符串的列表”，`str | None` 是“字符串或者空值”，`->` 后面写返回什么类型。它们主要是在说明接口，不会替你检查或转换输入。`from __future__ import annotations` 则让注解暂时不求值，第 16 章会用到这个细节。

## 卡住了，先看看这些地方

- sum_until_over 的条件是超过，不能把 <= 改成 <。
- 不要把偶数的值当成下标返回。
- while 忘记更新循环变量会一直执行。
